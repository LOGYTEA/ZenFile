# ZenFile 插件开发说明

## 一句话

插件是 **`ZenFile.exe` 的另一个进程**，不是独立 exe，也不是 DLL。

```
ZenFile.exe                    ← 宿主：窗口、托盘、文件操作
└── ZenFile.exe --plugin <id>  ← 插件：独立进程，崩了不影响宿主
```

## 为什么这样设计

| 需求 | 做法 | 原因 |
|---|---|---|
| 插件崩了不能带崩宿主 | 每个插件一个**进程** | 进程间没有共享地址空间，插件可以随便 panic、越界、死循环 |
| 不要一堆 exe 要单独升级 | 同一个 exe + `--plugin <id>` | 升级一次到位，版本永远一致 |
| 宿主退了不能留孤儿 | 全部挂进同一个 **Job Object** | `KILL_ON_JOB_CLOSE`，内核自动收掉 |
| 插件卡死也要能发现 | **心跳 + 超时**（5 秒） | 进程还活着不代表有用 —— 死循环 / 弹了个模态框都算卡死 |

**明确不提供**：hook 宿主内存、装 API hook、读宿主函数表。
想要新功能就改宿主代码重新编译，而不是塞一段机器码进去。

## 目录结构

插件放在 **`ZenFile.exe` 同级的 `plugins/` 目录**，每个插件一个子目录：

```
ZenFile.exe
plugins/
├── clipboard-history/
│   └── plugin.json          ← 必需
└── my-plugin/
    └── plugin.json
```

## plugin.json

```json
{
  "id": "my-plugin",
  "name": "我的插件",
  "description": "面板上显示在名字下面的一行说明",
  "protocol_version": 1,
  "autostart": false,
  "capabilities": ["core.log"]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✓ | 唯一标识，小写短横线。会出现在管道名与命令行参数里 |
| `name` | ✓ | 面板上显示的名字 |
| `description` | | 一行说明 |
| `protocol_version` | | 填 `0` 或不填 = 不校验；填了且与宿主不符则**拒绝加载**并在面板上说明原因 |
| `autostart` | | 随宿主自动启动。用户在面板上关掉插件后，以面板的设置为准 |
| `capabilities` | | 申请的能力。**没申请的调用宿主直接拒** |

### 可申请的能力

| 字符串 | 含义 |
|---|---|
| `clipboard.history` | 读剪贴板历史 |
| `screenshot.capture` | 触发截图 |
| `taskmgr.snapshot` | 拉取进程/性能快照 |
| `terminal.open` | 在当前目录开终端 |
| `preview.open` | 请求预览文件 |
| `core.log` | 写一行日志（**调试插件时先申请这个**） |

## 能力边界

插件进程里**没有**窗口、没有托盘、没有单实例互斥 —— 它拿不到：

- 宿主窗口句柄（不能画东西在宿主界面上）
- 托盘（不会在系统托盘挂图标）
- 别的插件的管道

能做的只有：申请能力、周期心跳、响应宿主调用。

## 调试

**先看面板**。「设置 - 插件」会显示每个插件的实时状态：

| 状态 | 含义 |
|---|---|
| 已禁用 | 你关掉了它 |
| 启动中 | 进程已拉起，还没握手 |
| 运行中 | 正常 |
| 无响应 | 心跳超时（5 秒没动静），会被杀掉重启 |
| 已停止 | 进程没了，正在等重启 |
| 启动失败 | 连续崩溃 3 次，或清单/协议有问题 |

崩溃次数只在真的崩过时显示，错误原因会直接写在状态后面。

**加一行日志**（最快的定位手段）：申请 `core.log` 能力，在处理逻辑里发：

```json
{"t":"result","id":<请求id>,"ok":true,"payload":{"msg":"我在这里"}}
```

## 崩溃了会怎样

1. 宿主在 100ms 的定时器里发现该插件的进程没了 → 面板状态变成「已停止」
2. 崩溃计数 +1，自动重新拉起
3. **连续崩溃 3 次后停止重启**，状态变成「启动失败」

上限是必须的：一个一启动就崩的插件（配置写错、依赖缺失）如果无限重启，
会变成"任务管理器里 ZenFile 疯狂拉进程"的灾难，比崩溃本身更糟。

## 常见问题

**面板显示"没有找到插件"**
`plugins/` 目录要和 `ZenFile.exe` 放在一起，不是 exe 的工作目录。

**面板显示"启动失败 · 读不到 ... plugin.json"**
清单路径不对，或 JSON 语法错误。`plugin.json` 必须在插件子目录里，不能写在 `plugins/` 根下。

**面板显示"协议版本不兼容"**
`plugin.json` 的 `protocol_version` 与宿主对不上。要么改清单，要么用当前版本重新出包。

**插件进程刚起来就退出**
多半是管道没连上。宿主是"先建管道再拉进程"的，正常会重试 2 秒；超过 2 秒还连不上，
说明宿主那边已经不在了。
